# TRIZ: examine an inventive contradiction

Use when improving one property worsens another, or the same element appears to need opposing properties. An ordinary preference tradeoff does not require TRIZ.

Describe the function to preserve, what must improve, what gets worse, and the operating conditions. Identify useful resources already present: time, space, information, existing components, or the surrounding process. Ask only for a missing detail that would materially change the problem model.

Choose a light way to reframe the contradiction: separate opposing needs in time, space, conditions, or different parts; remove a component and assign its function elsewhere; or describe the useful result without assuming the current solution is necessary. Move quickly from the abstraction to a few distinct candidate mechanisms and explain how each could help.

Distinguish an analogy or speculative concept from a validated design. Use relevant primary-source research when a mechanism's feasibility matters and tools are available; otherwise state what remains unverified. Do not invent contradiction-matrix entries, numbered principles, patent novelty, engineering measurements, or validation results. This pack contains no full TRIZ matrix, ARIZ implementation, or specialist reference database.

End with promising concepts and their tradeoffs or unresolved technical questions. No prototype, experiment, implementation, or standards sign-off is implied.

Adapted from Vladimir Kochetkov/v0lka's triz-solver; see [provenance](../PROVENANCE.md). The dialogue and light-tool selection remain; fixed concept counts, mandatory research breadth, and execution-oriented outputs are removed.
