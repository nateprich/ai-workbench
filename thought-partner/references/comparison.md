# Comparison: make tradeoffs visible

Use when viable alternatives compete on criteria the user cares about. A short qualitative comparison is enough for a simple two-option choice. For more alternatives, a table can expose the tradeoff.

Screen hard constraints first. Include the status quo or doing less when it is feasible. Identify distinct criteria without double-counting the same benefit under different names. Separate the user's priorities from claims about each option. Unknown evidence stays unknown; do not fill cells with invented scores or preferences.

Start qualitative. Use weighted scoring only when it would improve the decision and the user has supplied or accepted the weights and scale. Label judgments and estimates. Use reliable calculation when available and verify arithmetic; without it, keep the comparison qualitative rather than manufacture precision. This adaptation does not implement AHP or claim to provide the upstream MCDA tool.

Explain what assumption or change in priorities would reverse the recommendation. If plausible values favor different options, present a conditional choice or the missing evidence instead of declaring a robust winner. The purpose is to reveal the tradeoff, not bless a favorite with numbers.

Adapted from Claudio Babelis/radarist's decision-matrix-mcda; see [provenance](../PROVENANCE.md). This is a lighter qualitative comparison with optional simple scoring; no upstream scripts, mandatory rankings, or sibling skill dependencies are imported.
